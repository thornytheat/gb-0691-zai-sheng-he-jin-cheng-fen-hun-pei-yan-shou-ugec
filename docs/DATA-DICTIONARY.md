# 数据定义

元素质量按物料净重×含量汇总；干湿基转换，低于检出限给上下界，不可把未检出当零，配方版本锁定。

输入字段：lot, batch, mass, unit, moisture, element, assay, basis, revision。所有ID按字符串保留；空字符串、NULL、N/A、未知与“-”视为缺失，不能当作数值零。数值使用Decimal，输出为十进制字符串。重复业务键相同内容计重复，内容冲突隔离或按明确修订号裁决，不按文件顺序盲目覆盖。

每条证据有原始行号，隔离记录有原因码及原值。时间区间使用半开边界；日期定义在各模块规则内显式声明。输入表头可调序，不得缺列或重复；中文旧编码可上传。规则版本存入运行清单，重跑使用原始文件内容摘要与规则版本共同确定幂等键。复核使用revision乐观锁，陈旧提交返回409。

Cu和Zn目标区间为V1教学配方，不外推为生产工艺。缺测元素贡献范围按0–100%计；湿基换干基先除以干物质比例；样例存在只测单元素的料批，因此验收可能待补测。

混配按batch炉次独立计算；同一lot可在不同炉次出现，采信键为(batch,lot,element)，移除批次的试算也仅影响所属炉次。

## 复配补料（M7）

补料库存CSV字段：material_id, material_name, element, assay_pct, on_hand_kg。同一材料按元素分行登记化验，仅支持干基确定值；材料未化验的元素按0~100%保守区间参与补后上下界计算，不可当作零。库存数量全表一致，重复元素或负库存拒绝导入。

交期CSV字段：batch, due_date(YYYY-MM-DD，可空), priority（急单/普通）。未登记炉次按普通、交期排在最后处理。

剂量可行性按元素分别建立线性不等式再取交集：补料剂量x须同时满足各元素含量下界与上界约束，系数为负时不等号翻转；最小剂量按秤量分度0.001kg向上取整，取整后越过可行上界判不可行。补料后含量上下界按“原元素质量上下界＋剂量×材料含量上下界”除以新总重重算，验收判定与M6同规则（通过/不合格/待补测）。

整组分配顺序：急单先按交期升序、再按炉次号；普通炉次按各自最小可行耗料量升序轮候，先救耗料少的炉次。每炉在可行材料中选最小剂量者；所有可行材料库存均不足时标记未分配并列出“需多少/余多少”，绝不超领；已合格炉次免补料、不占库存。

确认键为`run_id:plan_hash`，plan_hash对运行批次、库存快照、分配明细与交期表取SHA256。确认与库存调整全部在`BEGIN IMMEDIATE`事务内执行，SQLite写锁串行化并发请求；同确认键重试返回原单据且不重复扣料，库存不足整单回滚。每次库存变动写入reblend_ledger台账（SEED/RESET/ADJUST/CONFIRM）。
